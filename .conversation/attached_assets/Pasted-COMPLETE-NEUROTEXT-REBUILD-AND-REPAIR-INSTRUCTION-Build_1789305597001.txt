COMPLETE NEUROTEXT REBUILD AND REPAIR INSTRUCTION

Build a complete, production-quality version of NEUROTEXT. Preserve the existing interface, branding, routes, terminology, user flows, and all working functionality. Do not replace the interface with a generic dashboard. Do not remove features merely because they are difficult to implement. Do not use mocked generation, fake streaming, fabricated diagnostics, placeholder counters, or hardcoded successful results.

NEUROTEXT is a ten-function document-intelligence platform. Its central purpose is to create, transform, analyze, improve, profile, translate, and transfer substantial documents using selectable language models.

The most important technical requirement is genuine visible streaming. The second most important requirement is reliable long-document generation from 100 through 100,000 requested words.

1. THE TEN DOCUMENT FUNCTIONS

Implement and preserve these ten separate functions:

Function 01: Document Creator & Manipulator

Create a new document from instructions alone or transform supplied source material. It must support essays, research papers, reports, articles, books, chapters, arguments, rewrites, expansions, reductions, and other document forms.

Function 02: Objections & Bullet-Proof Rewrite

Identify the strongest serious objections to the supplied document. Explain why each objection matters. Produce a revised document that directly addresses the objections without abandoning the source’s central thesis unless the user explicitly requests a change in position.

Function 03: Screenplay Generator

Create or transform material into a properly formatted screenplay with scene headings, action, character cues, and dialogue.

Function 04: Dialogue Generation

Create vivid, natural, character-distinct dialogue from instructions or supplied source material.

Function 05: Coherence Evaluator

Analyze the document’s structural, argumentative, conceptual, and evidential coherence. Provide a useful report and scorecard. Include an “Improve coherence” action that streams a revised, publication-ready document.

Function 06: Maximum Intelligence Rewriter

Rewrite the document to maximize clarity, precision, reasoning quality, evidence, conceptual depth, and intellectual rigor. Preserve the source’s thesis, distinctive ideas, terminology, examples, negative results, and factual content.

Function 07: Cognitive Profiling

Produce a careful cognitive profile based only on the supplied writing. Analyze reasoning style, abstraction, conceptual habits, assumptions, distinctions, use of evidence, strengths, and limitations. Do not diagnose the author or infer unsupported sensitive personal attributes.

Function 08: Master’s Thesis Creator

Create a complete, coherent scholarly master’s thesis from instructions alone or supplied research material. It must support the user’s requested length, including requests such as 20,000 words. A short essay must never be presented as a completed thesis.

Function 09: Dissertation Creator

Create a complete scholarly dissertation from instructions alone or supplied research. It must support large requested lengths and preserve continuity across all chapters and sections.

Function 10: Document Translation

Translate the supplied document as instructed while preserving structure, terminology, meaning, quotations, citations, and factual claims.

5. TARGET WORD LENGTH

Accept every integer from 100 through 100,000.

The generator must aim at the exact requested number. The acceptable final margin is a validation boundary, not the generation goal.

Never generate toward the minimum acceptable boundary.

Never replace the requested target with an arbitrary example such as 2,000 or 3,000 words.

The final error must never exceed 10%.

Larger requested documents should have a smaller final error than shorter documents.

Do not invent a more specific tolerance formula unless the product owner explicitly approves it.

Overlength documents may be trimmed deterministically to the requested target, but trimming must preserve paragraph breaks, headings, citations, punctuation, and formatting.

Never split all words and rejoin them with spaces. That destroys paragraphs and is prohibited.

Underlength documents must be expanded with substantive continuation until they reach the approved range.

The displayed word counter must calculate the words in the actual rendered document.

A document outside the approved range must not display “Complete.”

6. GENUINE VISIBLE STREAMING

Streaming is the highest-priority user experience.

The Live Document must display generated prose immediately and continue growing as generation proceeds.

A blank Live Document followed by a completed block is a total failure.

Receiving server events without visible DOM growth is also a failure.

Streaming proof requires repeated growth in:

data-testid="live-document-text"

and

data-testid="live-word-count"

The browser must show multiple increasing word counts before completion.

The streaming path must use one dedicated server transport module:

artifacts/api-server/src/services/live-document-stream.ts

That module must exclusively manage:

Content-Type: text/event-stream.

No-cache and no-transform headers.

Disabled proxy buffering.

Identity content encoding.

Immediate header flushing.

Socket no-delay.

Socket keepalive.

Sufficient initial SSE padding to exceed reverse-proxy buffering thresholds.

Regular heartbeat comments.

Flushing after every event.

Safe handling of disconnected clients.

Heartbeat cleanup when the request closes or finishes.

All document-streaming and coherence-streaming routes must use this module. Do not duplicate streaming-header logic across routes.

Generated model tokens must be forwarded to the browser as they arrive.

If a provider emits an oversized text delta, split it into small, paced word groups before forwarding it. Do not wait for the completed provider response.

The client must append incoming token events to the Live Document immediately.

Use a controlled animation-frame update only to prevent excessive rendering. Do not delay visible output until a section completes.

Do not confuse skeleton or outline tokens with document prose. Internal planning may be generated, but visible finished prose must receive priority.

Opening prose must start before hidden blueprint generation can consume provider capacity.

Never run a hidden blueprint request concurrently in a way that blocks visible opening prose.
