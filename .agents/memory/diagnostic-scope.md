The user requires a button-driven diagnostics suite that tests every function. Short functions generate a complete product; master's thesis and dissertation functions generate only bounded samples. Test speed and actual incremental text delivery, not just HTTP success.

**Why:** The user explicitly requested every function, speed, and streaming after failures that verbal assurances did not resolve.

**How to apply:** Include output-rewrite actions as well as initial generation, retain exact inputs and outputs as inspectable evidence, label academic sample coverage accurately, and never convert a failed, buffered, or unmeasured result into a green success.

Adaptive-model output limits also cover internal reasoning. A tiny academic preview budget can finish with only a title or no visible text even when the underlying writing function works.

**Why:** Live diagnostic samples exhausted their entire small allowance before generating substantive output.

**How to apply:** Bound previews to one request with no continuation, but reserve enough budget for reasoning plus a meaningful sample. Check actual sample substance instead of treating any nonempty response as success.
