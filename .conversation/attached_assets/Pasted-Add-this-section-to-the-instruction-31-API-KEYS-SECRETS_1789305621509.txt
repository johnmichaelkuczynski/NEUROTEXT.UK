31. API KEYS, SECRETS, AND ENVIRONMENT CONFIGURATION

Use Replit Secrets for every API key, OAuth credential, webhook secret, database connection, and session secret.

Never hardcode secret values in source code.

Never place secret values in frontend environment variables.

Never send secret values to the browser.

Never print secret values in logs, diagnostics, error messages, screenshots, generated documents, or API responses.

Never ask the user to paste secret values into chat.

Use these existing server-side secret names:

AI_INTEGRATIONS_OPENAI_API_KEY

AI_INTEGRATIONS_OPENAI_BASE_URL

AI_INTEGRATIONS_ANTHROPIC_API_KEY

AI_INTEGRATIONS_ANTHROPIC_BASE_URL

GENIUS_API_KEY

GOOGLE_CLIENT_ID

GOOGLE_CLIENT_SECRET

SESSION_SECRET

DATABASE_URL

STRIPE_SECRET_KEY

STRIPE_WEBHOOK_SECRET

OpenAI requests must use:

AI_INTEGRATIONS_OPENAI_API_KEY

AI_INTEGRATIONS_OPENAI_BASE_URL

Anthropic requests must use:

AI_INTEGRATIONS_ANTHROPIC_API_KEY

AI_INTEGRATIONS_ANTHROPIC_BASE_URL

GENIUS requests must use:

GENIUS_API_KEY

Google authentication must use:

GOOGLE_CLIENT_ID

GOOGLE_CLIENT_SECRET

Application sessions must use:

SESSION_SECRET

Database access must use:

DATABASE_URL

Stripe server requests must use:

STRIPE_SECRET_KEY

Stripe webhook verification must use:

STRIPE_WEBHOOK_SECRET

All AI-provider calls must originate from the API server. The React frontend must call NEUROTEXT’s own server routes and must never call OpenAI, Anthropic, GENIUS, Google, Stripe, or the database directly.

Do not create duplicate API clients when an existing configured integration client is available.

Fail explicitly when a required secret is unavailable. Return a safe message naming the missing configuration variable, but never expose another secret’s value.

Do not silently replace a missing provider with fake output.

Provider fallback is allowed only among genuinely configured providers.

The selected provider must be tried first. If it fails and fallback is permitted, record the provider that actually completed the request.

Production and development must use their respective secure environment configurations. Do not copy development secrets into source code or deployment configuration files.

Use HTTPS for every external provider request.

Verify Google OAuth state and redirect handling.

Use secure, HTTP-only, same-site session cookies.

Verify Stripe webhook signatures using the raw request body and STRIPE_WEBHOOK_SECRET.

Do not expose DATABASE_URL to browser code.

Do not expose owner authorization through a client-controlled flag.

Diagnostics may report provider names, request timing, and safe error categories. Diagnostics must never display API keys, authorization headers, cookies, tokens, database connection strings, OAuth codes, webhook signatures, or raw provider credentials.
